# Style Guide "Функциональная ясность"

1. **Простые, однозадачные функции**
   - Каждая функция решает одну задачу
   - Минимум побочных эффектов
   - Длина функции не более 20-30 строк

2. **Явная обработка ошибок**
   - Fail-fast при невалидных входных данных и обработке ошибок, избегаем лишних try/finally
   - Создаем собственные классы исключений при необходимости
   - Информативные классы исключений
   - Подробные сообщения об ошибках

3. **Минимальные зависимости**
   - Избегать излишних абстракций
   - Предпочитать стандартную библиотеку
   - Инкапсулировать внешние зависимости

4. **Современный Python**
   - Python 3.11+
   - Контекстные менеджеры вместо try/finally
   - Библиотека pathlib вместо os.path
   - Статическая типизация аргументов и возвращаемых значений с использованием современного синтаксиса

5. **Документация и наименования**
   - Говорящие имена функций и переменных
   - Docstrings с подробным описанием аргументов, результатов и ошибок
   - Комментарии для сложных алгоритмов, но не для очевидного кода

6. **Организация кода**
   - Публичный API с четким интерфейсом
   - Функции-помощники скрыты от внешнего пользователя
   - Группировка по функциональности, не по типу

7. **Тестируемость**
   - Чистые функции, не зависящие от состояния
   - Изоляция сторонних эффектов
   - Явные входные и выходные параметры
   - Error Hiding антипаттерн**: В тестах используйте `pytest.fail()` вместо `raise TimeoutError()`. Обычные исключения подвержены **Error Hiding** (поглощению исключений) - антипаттерну, когда промежуточные слои кода ловят исключения и "проглатывают" их без надлежащей обработки или логирования. Это создает ложное ощущение стабильности при потере критической диагностической информации.

8. **Timeout как обязательная защита**

**Принцип**: Все блокирующие операции в тестах должны иметь timeout для предотвращения зависания. Все внешние вызовы должны иметь timeout

**Критическое замечание**: Timeout не должен маскировать логические ошибки. Если функционал зависает без timeout - это сигнал о проблеме в логике, а не повод добавить timeout.

**Техническая деталь - Error Hiding антипаттерн**: В тестах используйте `pytest.fail()` вместо `raise TimeoutError()`. Обычные исключения подвержены **Error Hiding** (поглощению исключений) - антипаттерну, когда промежуточные слои кода ловят исключения и "проглатывают" их без надлежащей обработки или логирования. Это создает ложное ощущение стабильности при потере критической диагностической информации.

**Применение**:
```python
# Правильно - тест явно падает с понятным сообщением
if not event.wait(timeout=2.0):
    pytest.fail(f'Test design error: timeout waiting for {event_key=}')

# Неправильно - исключение может быть поглощено
if not event.wait(timeout=2.0):
    raise TimeoutError(f'Test design error: {event_key=}')
```
